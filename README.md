# Bottom — крипто-ресерчер в Telegram

ИИ-агент, которому можно задавать вопросы о крипте: разбор монеты, деривативы,
стакан, DEX и безопасность контракта, новости и слухи, X и Telegram-каналы (вместе с
картинками авторов), сетапы с проверенным расчётом. Сопоставляет новости из всех источников
между собой и с ценой, учится на своих ошибках. Сам сигналы не публикует — только отвечает.
Спецификация всей системы: [`docs/agent-spec.md`](docs/agent-spec.md).

## Как это работает

```
вопрос → модель решает, какие данные нужны → инструменты собирают данные
       → модель пишет разбор → сетап проходит валидатор (calc_setup) → ответ
```

- **Правила для модели** — `bottom/prompts.py`: цифры только из инструментов, иерархия
  доверия к источникам и как сопоставлять новости, порядок сбора, как читать
  OI/фандинг/стакан, жёсткие правила сетапов, формат ответа, работа над ошибками.
- **Примеры ответов** — `bottom/examples.py`: разборы в стиле эталонных образцов (причины
  роста, честный отказ, колл, «жду точку», ответ в чате, проверка слуха, разбор скрина) и
  реальные ошибки, которые повторять нельзя.
- **Валидатор сетапов** — `bottom/tools/setup_calc.py`: минимальный стоп (по классу актива
  и ATR), минимальный R:R, таблица потерь по плечам. Модель не имеет права показать сетап
  без вердикта OK.
- **Модель подключается конфигом**: любой OpenAI-совместимый API (бесплатные модели
  OpenRouter, Groq, Gemini, локальная Ollama) или Claude.

### Инструменты

| Инструмент | Что делает | Источник |
|---|---|---|
| `resolve_token` | какой именно токен (защита от однофамильцев) | CoinGecko |
| `market_overview` | цены спот/перп на 9 биржах, базис, разброс | ccxt |
| `derivatives` | фандинг, OI и его динамика, лонги/шорты, taker flow | Binance, Bybit, OKX + ccxt |
| `candles` | EMA, RSI, Stoch, ATR, уровни, дельта/CVD, объём | Binance / ccxt |
| `orderbook` | глубина, перекос, стенки | ccxt |
| `token_fundamentals` | MCap, FDV, эмиссия, категории, ATH | CoinGecko |
| `dex_pairs` | пары, ликвидность, объём, возраст | DexScreener |
| `token_security` | honeypot, налоги, холдеры, LP | GoPlus |
| `defi_protocol` | TVL и динамика | DefiLlama |
| `market_sentiment` | Fear & Greed, доминация, тренды | alternative.me, CoinGecko |
| `crypto_news` | заголовки крипто-СМИ | RSS, CryptoPanic (опц.) |
| `telegram_channels` | сообщения крипто-каналов и чатов: упоминания монеты, что обсуждают, лента конкретного канала целиком, описания картинок | Telegram (твой аккаунт) |
| `cross_check` | одна новость/тикер по всем источникам: кто первый, независимые подтверждения, волны репостов, реакция цены до и после | Telegram + X + СМИ + биржи |
| `analyze_image` | разбор картинки: график с уровнями, скрин позиции, скрин новости | модель со зрением |
| `track_record` | собственная статистика сетапов: исходы, винрейт, R, MFE/MAE | журнал бота |
| `x_discussion`, `x_influencers` | новости и мнения в X (только с ключом) | twitterapi.io |
| `web_search` | поиск в интернете и свежих новостях (с датами) — работает без ключей | Tavily → Brave → DuckDuckGo |
| `fetch_page` | чтение страницы целиком (статья, анонс, документация) | Jina Reader → напрямую |
| `calc_setup` | проверка и расчёт сетапа | свой код |

X используется **только для новостей и мнений инфлюенсеров**, не для цифр рынка.
Список аккаунтов — `X_ACCOUNTS` в `.env` (по умолчанию — в `bottom/config.py`).

## Запуск

> **Windows без командной строки:** пошаговая инструкция — [`docs/windows.md`](docs/windows.md)
> (`install.bat` → `check.bat` → `scan_channels.bat` → `start.bat`; без бота — `scan_channels.bat` и `tg_collect.bat`).
> Проверить настройки на любой системе: `python -m bottom.check`.

1. **Бот в Telegram.** Напиши [@BotFather](https://t.me/BotFather) → `/newbot` → получи токен.
2. **Основная модель — Gemini (бесплатно).**
   - Открой <https://aistudio.google.com/apikey>, войди в Google-аккаунт → **Create API key**.
   - Карта не нужна, работает бесплатный тариф (Flash-модели). Подписка Google AI Pro для
     API не нужна и лимиты API не повышает.
   - Имя модели возьми в AI Studio (выпадающий список моделей) — последняя `gemini-…-flash`.
   - На бесплатном тарифе Google может использовать запросы для улучшения моделей.
   - AI Studio доступен не во всех странах; если страница не открывается — это ограничение региона.
3. **Запасная модель — OpenRouter (бесплатно).**
   - Зарегистрируйся на <https://openrouter.ai> → <https://openrouter.ai/settings/keys> → **Create Key**.
   - Выбери бесплатную модель **с поддержкой инструментов**:
     <https://openrouter.ai/models?max_price=0&supported_parameters=tools>
     (id заканчивается на `:free`). Список меняется — если модель пропала, возьми другую.
   - У бесплатных моделей OpenRouter дневной лимит запросов на аккаунт; точные цифры — в
     документации OpenRouter.
4. **Настройки.**
   ```bash
   cp .env.example .env
   # заполни TELEGRAM_BOT_TOKEN, LLM_API_KEY, LLM_MODEL, FALLBACK_LLM_API_KEY, FALLBACK_LLM_MODEL
   ```
5. **Установка и старт** (Python 3.11+):
   ```bash
   python -m venv .venv && source .venv/bin/activate
   pip install -e .
   python -m bottom
   ```
   Или в Docker:
   ```bash
   docker build -t bottom . && docker run --env-file .env -v $(pwd)/data:/data bottom
   ```
6. Напиши боту `/start`. В логе при старте видно, какие модели подключены:
   `llm=openai:gemini-… → openai:z-ai/…:free`.

### Запасная модель
Если основная модель вернула ошибку, упёрлась в лимит или ответила пусто, бот продолжает
тот же вопрос на запасной — уже собранные данные не теряются (обе модели работают через
OpenAI-совместимый API). Основная отключается на время: при дневной квоте на час, при
поминутном лимите на 2 минуты, в остальных случаях на `LLM_COOLDOWN_SEC`. Переключения
пишутся в лог (`LLM … failed → fallback …`). Если запасная не задана — работает только основная.

### Telegram-источники (через твой аккаунт)
Реестр — `channels/sources.json`: 194 источника (каналы, чаты, чаты с темами; 160 публичных
и 34 приватных). Ключ источника — числовой id чата: юзернеймы меняются и пропадают, id — нет.

**Как читаем.** Всё — и публичное, и приватное — через сессию твоего аккаунта (Telethon):
аккаунт уже состоит во всех источниках, поэтому
- **новые сообщения приходят вживую** (updates) — без опроса, сразу, минимальная нагрузка
  на аккаунт;
- **история**: при первом запуске читается `TG_BACKFILL_DAYS` дней (по умолчанию 30, `0` —
  весь канал целиком; для 194 источников это долго), дальше раз в `TG_RESYNC_MINUTES`
  догружается всё с последнего сохранённого id — на случай, если сборщик был выключен;
- сохраняются посты с картинками (в т.ч. без текста) и альбомы; из чатов — автор и тема
  форума; пустые и односимвольные сообщения пропускаются;
- храним `TG_KEEP_DAYS` дней (по умолчанию 180).

Публичные каналы можно было бы читать и без аккаунта (веб-превью `t.me/s/…`), но это не
нужно: аккаунт всё равно нужен для приватных, а живые обновления через него быстрее и
надёжнее опроса.

**Приватное остаётся приватным.** Сообщения приватных источников бот использует как фон:
не цитирует дословно, не называет источник и не даёт ссылку (`TG_SHOW_PRIVATE=true`
разрешает).

Шаги:
1. `api_id` и `api_hash`: <https://my.telegram.org> → **API development tools** → создай
   приложение. Можно не вписывать в `.env` — команды спросят сами и сохранят.
2. Проверка источников (один раз; при первом запуске — вход по номеру и коду из Telegram):
   ```bash
   python -m bottom.tg scan       # --include-dialogs — добавить все каналы/чаты аккаунта
   ```
   Для каждого источника: доля сообщений с крипто-лексикой (тикеры, биржи, лонг/шорт,
   контракты, pump.fun…), в чатах — по более длинным сообщениям. Результат пишется в
   `sources.json` (`verdict`, `enabled`) и в отчёт `channels/report.md`. Некрипто —
   выключаются; сомнительные остаются включены (список уже отобран вручную); `--llm`
   доразберёт сомнительные моделью. `"manual": true` — scan не трогает `enabled`.
3. Сбор: запускается сам вместе с ботом. Без бота: `python -m bottom.tg collect`
   (`--once` — только догрузить и выйти). Посмотреть собранное:
   `python -m bottom.tg search BTC`.

Файл `data/telegram.session` **даёт полный доступ к аккаунту** — не публикуй и не коммить
(уже в `.gitignore`).

В Docker вход делается интерактивно: `docker run -it --env-file .env -v $(pwd)/data:/data bottom python -m bottom.tg login`.

### Картинки
Графики, скрины позиций и новостей из каналов разбирает модель со зрением (по умолчанию —
основная, Gemini Flash умеет): свежие картинки — в фоне (каналы раньше чатов, не больше
`VISION_DAILY_LIMIT` в день), остальные — по запросу бота (`analyze_image`). Картинки из
твитов и присланные пользователем боту — тоже.

### Сопоставление новостей
`cross_check` собирает тему из Telegram-каналов и чатов, X, СМИ и свежих новостей из интернета в одну хронологию: кто
написал первым, сколько независимых источников (копии одного текста считаются одной
волной репостов), есть ли официальный источник, и как вела себя цена за 6 часов до
первого упоминания и после. Правила чтения — в разделе 2 инструкций (`bottom/prompts.py`).

### Обучение на ошибках
1. **Журнал.** Каждый сетап, который бот выдал (прошёл `calc_setup` и попал в ответ),
   записывается.
2. **Исход.** Раз в 30 минут по часовым свечам проверяется, что было: вход не исполнился /
   стоп / TP1 → безубыток / TP2 / истёк; считаются R, MFE и MAE. Правила консервативные:
   вход по худшей границе зоны, стоп и цель в одной свече — считается стоп.
3. **Жалобы.** Пользователь отвечает на разбор бота командой `/wrong что не так`.
4. **Разбор.** Раз в сутки (`LEARN_HOUR_UTC`) модель читает закрытые сетапы и жалобы и
   предлагает короткие уроки, каждый — со ссылками на случаи, на которых он основан
   (S12 — сетап, F3 — жалоба). Ссылки проверяются кодом: сослаться можно только на случаи
   из этого разбора.
5. **Урок надо заслужить** (методология `agent-memory` / `memory-engineering`):
   - новый урок — **кандидат**, в инструкции бота он НЕ попадает;
   - **применяется** только после подтверждения ≥ 2 разными случаями в ≥ 2 разных дня,
     или если админ его утвердил (`/adopt N`, `/lesson текст`);
   - если факты противоречат уроку, он не удаляется, а помечается **спорным** — остаётся
     в инструкциях с пометкой, решает человек (`/adopt` или `/forget`);
   - **забывание:** кандидат живёт 30 дней, применяемый авто-урок без подтверждений —
     60 дней, одновременно не больше 30 уроков (уроки админа не вытесняются).
6. **Применение.** Статистика и уроки добавляются в инструкции бота (раздел «Опыт»), а
   перед новым сетапом он смотрит свою историю через `track_record`.

### Защита от выдуманных цифр и зацикливания
- **Проверка чисел** (`bottom/grounding.py`) — кодом, не моделью: числа из ответа
  сверяются с данными инструментов, вопросом и правилами. Если много чисел не найдено —
  модель один раз переписывает ответ с перечнем этих чисел.
- **Ограничения:** бюджет шагов на вопрос; одинаковые вызовы инструментов берутся из кеша;
  ход без новых вызовов тоже тратит шаг; таймаут 60 с на инструмент и 5 минут на весь ответ.

### Группы
Добавь бота в группу. Он отвечает, если его упомянули через `@имя_бота` или ответили
на его сообщение. Режим приватности BotFather можно не трогать — бот и так получает
такие сообщения. Если ответить боту реплаем на чужое сообщение с упоминанием, он учтёт
его текст как контекст.

### Команды
`/start`, `/help` — FAQ · `/limit` — остаток шагов на сегодня · `/reset` — очистить контекст ·
`/wrong текст` (ответом на разбор) — сообщить об ошибке · `/stats [тикер]` — статистика сетапов ·
`/lessons` — уроки (✅ применяю · ⚠️ спорный · 🕐 кандидат) · `/lesson текст`, `/adopt N`,
`/forget N` — управление уроками (админ).
Можно прислать боту картинку (график, скрин) — разберёт.

## Настройки

| Переменная | Что это |
|---|---|
| `LLM_PROVIDER` | `openai` (любой OpenAI-совместимый API) или `anthropic` |
| `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL` | основная модель |
| `FALLBACK_LLM_*` | запасная модель (те же четыре поля) |
| `LLM_COOLDOWN_SEC` | на сколько отключать основную после ошибки (600) |
| `MAX_STEPS_PER_QUESTION` | максимум вызовов инструментов на один вопрос (12) |
| `DAILY_STEPS_PER_USER` | дневной лимит шагов на пользователя (50) |
| `ADMIN_IDS` | Telegram id без лимита |
| `EXCHANGES` | биржи ccxt |
| `MIN_RR`, `MIN_STOP_PCT_MAJOR`, `MIN_STOP_PCT_ALT`, `MIN_STOP_ATR_MULT`, `MAJORS` | правила валидатора |
| `TWITTERAPI_IO_KEY`, `X_ACCOUNTS` | X: ключ [twitterapi.io](https://twitterapi.io) и список аккаунтов |
| `TG_API_ID`, `TG_API_HASH`, `TG_SESSION` | Telegram-аккаунт для чтения каналов |
| `TG_SOURCES_FILE`, `TG_RESYNC_MINUTES` | реестр источников и как часто догружать пропущенное |
| `TG_SHOW_PRIVATE` | разрешить боту называть приватные источники и давать ссылки |
| `TG_BACKFILL_DAYS`, `TG_KEEP_DAYS` | глубина первого чтения истории (0 — весь канал) и сколько хранить |
| `VISION_LLM_*`, `VISION_DAILY_LIMIT` | модель для картинок (по умолчанию основная) и дневной лимит |
| `LEARN_HOUR_UTC` | час ежедневного разбора ошибок |
| `TAVILY_API_KEY`, `BRAVE_API_KEY` | необязательные ключи поиска ([Tavily](https://tavily.com), [Brave](https://brave.com/search/api/)); без них — DuckDuckGo |
| `WEB_READER`, `JINA_API_KEY` | чтение страниц: `jina` (по умолчанию) или `direct` |
| `COINGECKO_API_KEY` | демо-ключ CoinGecko (выше лимиты) |
| `CRYPTOPANIC_API_KEY` | новости CryptoPanic |

### Переход на Claude
```env
LLM_PROVIDER=anthropic
LLM_API_KEY=...              # ключ Anthropic
LLM_MODEL=claude-opus-5      # или claude-sonnet-5 — дешевле
```
Бесплатную модель можно оставить запасной (`FALLBACK_LLM_*`).
Для `claude-opus-5` включён серверный фолбэк при отказе модели (`fallbacks: "default"`).

## Разработка

```bash
pip install -e ".[dev]"
pytest
```
Тесты не ходят в сеть: валидатор проверяется на реальных примерах колов (опубликованные
колы проходят, ошибочные сетапы из чатов отклоняются), плюс индикаторы, форматирование,
цикл агента и формат сообщений обоих провайдеров.
