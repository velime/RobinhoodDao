# Спецификация: крипто-ИИ-агент (ресерчер + автоматические колы)

Цель — собрать систему уровня Swarm AI / Maga AI calls: ИИ-агент, который
по запросу делает разбор монеты по всем источникам, а в автоматическом режиме
разбирает алерты и публикует колы в Telegram-ветку.

Документ основан на разборе реальных сообщений Swarm AI и Maga AI calls
(экспорт чата, скриншоты ветки, ответы бота о своих инструментах).

---

## 1. Что мы узнали об оригинале

### 1.1. Три режима на одном ядре
| Режим | Где | Триггер | Выход |
|---|---|---|---|
| **Ресерчер** (Swarm AI) | личка бота | вопрос пользователя | подробный разбор |
| **Чат-бот** | групповые чаты | упоминание `@bot` или реплай на сообщение бота | короткий ответ с сетапом |
| **Caller** (Maga AI calls) | ветка в супергруппе | алерт из алерт-софта Ultra | call / watch / обновление / отмена |

### 1.2. Инструменты (по словам самого бота и статусам)
Статусы во время ответа: «Сверяю цены на биржах», «Работаю с данными»,
«Ищу в вебе», «Смотрю Binance», «Смотрю Gate.io», «Смотрю DEX-пары».
Инструменты разделены по источникам, есть сводный по биржам, есть выполнение
кода для расчётов, есть веб-поиск.

Порядок сбора, который описал бот:
1. цена и базис по всем биржам (где реальная ликвидность);
2. фандинг и OI (кто платит, растёт ли интерес);
3. позиции L/S и стакан (где стоят деньги);
4. уровни и свечи (структура);
5. ончейн и безопасность контракта — в конце, чтобы отсеять мусор.

Чего у него нет или работает частично: CVD, лента ликвидаций (каскады читает
через стакан и дельту), стакан перпов MEXC, часть пар Hyperliquid,
собственный индексатор Robinhood Chain (только веб-поиск).

### 1.3. Правила caller'а (видны по постам)
- Вход **только лимитом**, в погоню не заходим. Если R:R от текущих плохой —
  вход переносится на откат.
- После вертикали приоритет — откат («по нашему плейбуку»); шорт на снятии
  ликвидности над хаем.
- Стоп — за 1ч/4ч пулом ликвидности; тейки — перед уровнями.
- TP1 → стоп в безубыток, затем TP2.
- **Минимальная дистанция стопа зависит от монеты** (EUL ≥7.8%, BANK ≥9.6%) —
  считается от волатильности, скорее всего через ATR. Если стоп уже минимума —
  публикуется **watch** вместо сигнала.
- В опубликованных колах R:R к TP1 — от 1.4 до 3.4, все цифры сходятся при
  пересчёте → их считает код.
- Идеи живут во времени: watch → сигнал → обновления → отмена/разворот
  (пример RE: «картина перевернулась, идею на шорт отменяем»). Обновления
  публикуются реплаем на исходный пост.

### 1.4. Слабые места оригинала (не повторяем)
- **В личке и чатах нет валидатора.** PENGU: «R:R ≈ 1:3–5», а к TP1 реально
  ≈0.24. RE: лонг на пробое $0.4750 с целью $0.4768 (+0.4%) при риске 2.7%,
  подано как «R:R около 1:1».
- **Невыполнимые watch.** EUL/BANK: зона ожидания включает текущий вход, и стоп
  внутри неё никогда не станет шире минимума.
- **Нет общей памяти между режимами.** Swarm в личке не знал об отменённой
  идее по RE из ветки caller'а.
- **Нет определения тикера.** «AI» на OKX и Gate — разные рынки (разброс 11%).
- **Robinhood Chain только через веб-поиск** — нет данных по конкретным токенам.

## 2. Архитектура

```
                    ┌──────────────────── ОБЩЕЕ ЯДРО ─────────────────────┐
 Алерты Ultra ────► │ Ticker Resolver → Data Tools → Feature Calculator   │
 Пользователи ────► │ Validator / Risk Calculator                         │
                    │ Storage: алерты, идеи и статусы, память диалогов    │
                    │ Price Monitor (без LLM)                             │
                    └──────┬──────────────────┬──────────────────┬────────┘
                           │                  │                  │
                    Caller (автомат)    Чат-бот (группы)    Ресерчер (личка)
                    фиксированный       агент с лимитом     агент, 15–20 шагов
                    конвейер            шагов
                           │                  │                  │
                           └────────── Telegram Renderer ────────┘
```

Принцип: **код решает, модель объясняет.** Всё, что можно посчитать, считает
код (базис, изменения OI, уровни, ATR, R:R, % до стопа, плечо). Модель выбирает
сценарий и пишет текст. Любые цифры в тексте модели проходят валидатор.

### 2.1. Модули
| Модуль | Ответственность |
|---|---|
| **Ticker Resolver** | тикер/адрес → конкретный токен: CoinGecko id, контракты по сетям, пары на каждой бирже. Отбрасывает однофамильцев (LIT ≠ Lighter, AI на OKX ≠ AI на Gate). Если неоднозначно — уточняет у пользователя. |
| **Data Tools** | обёртки над API бирж, DEX, ончейна, новостей. Возвращают нормализованные данные, не сырые ответы. |
| **Feature Calculator** | базис, разброс между биржами, ΔOI за окна, фандинг-ряд, L/S сводно, дельта потока, перекос и стенки стакана, пулы ликвидности 1ч/4ч (свинг-хаи/лоу), позиция в суточном диапазоне, ATR, RSI/EMA/Stoch, оборот/MCap, FDV/MCap. |
| **Validator / Risk Calculator** | проверяет сетап (раздел 5), считает R:R, % до стопа, плечо, потерю депозита. Отклоняет или понижает сигнал до watch. |
| **Storage** | алерты Ultra, идеи и их статусы, id сообщений в Telegram, память диалогов. |
| **Price Monitor** | цикл без LLM: проверяет вход в зону, пробой отмены, тейки, закрытие свечи выше/ниже уровня. При смене статуса вызывает модель для текста обновления. |
| **Telegram Renderer** | шаблоны постов (раздел 6), прогресс-статусы, свёрнутые цитаты. |

## 4. Состояния идеи

```
          алерт
            │
            ▼
        [ФИЛЬТР] ── шум ──► SKIPPED (не публикуется, пишется в базу)
            │
            ▼
        [АНАЛИЗ + ВАЛИДАТОР]
            │
     ┌──────┴────────┐
     ▼               ▼
   WATCH ───────► ACTIVE ──► TP1_HIT (стоп в б/у) ──► TP2_HIT / CLOSED
     │  условие      │
     │  выполнено    ├──► STOPPED
     │               │
     └──► CANCELLED ◄┴──► REVERSED (идея развернулась → новая идея)
```

- Переходы WATCH → ACTIVE, ACTIVE → TP/STOP/CANCELLED определяет **Price Monitor**
  по правилам (зона, уровень отмены, закрытие свечи), без модели.
- Модель вызывается только для текста поста при смене статуса и для
  пересмотра идеи, когда по той же монете пришёл новый алерт.
- Каждое обновление публикуется **реплаем** на исходный пост идеи.
- Все режимы (caller, чат, ресерчер) видят активные идеи по монете и
  упоминают их в ответе.

## 5. Валидатор (правила по умолчанию)

Все пороги — в конфиге, стартовые значения калибруем на истории.

| Правило | Стартовое значение | Действие при нарушении |
|---|---|---|
| Минимальная дистанция стопа | `k × ATR(14, 1h) / цена`, k подбираем (ориентир по оригиналу: 7–10% на альтах) | сначала попробовать отодвинуть стоп за следующий уровень и пересчитать; не вышло → watch |
| Минимальный R:R к TP1 | 1.5 | перенести вход на откат; не вышло → watch |
| Вход от текущей цены | не дальше 1.5 × ATR(1h) | watch с зоной входа |
| Стоп за уровнем | стоп за ближайшим пулом ликвидности 1ч/4ч | сдвинуть стоп |
| TP перед уровнем | TP не дальше уровня сопротивления/поддержки | сдвинуть TP |
| Согласованность watch | зона ожидания обязана давать валидный стоп и R:R | не публиковать противоречивый watch |
| Свежесть данных | данные старше N секунд не используются | пересобрать данные |
| Ликвидность | минимальный объём и глубина стакана | пропуск или пометка «микрокап, размер маленький» |

Risk Calculator для каждого сетапа выдаёт: R:R к каждой цели, % до стопа,
для плеч 3x/5x/10x/20x — потерю депозита при стопе и прибыль при целях.
Эти цифры модель **вставляет**, а не считает.

## 6. Шаблоны сообщений

Форматирование — Telegram HTML; «Проверка» — свёрнутая цитата
(`<blockquote expandable>`).

### 6.1. Call
```
📣 Maga AI call — $TICKER

🔍 Проверка  (свёрнуто)
  MCap, перп-цена по биржам, ΔOI и Δцены 24ч/4ч, фандинг и время расчёта,
  L/S, оборот/MCap, катализатор (есть/нет), ончейн, алерты Ultra за окно

💡 Идея
  тезис в 2–4 предложения + что сломает идею

🎯 Сетап
  Лонг/Шорт перп, биржа
  Вход: лимит X (почему здесь)
  Стоп: X (+N%, за каким уровнем)
  Слом идеи: закрытие 1ч выше/ниже X
  TP1: X (перед каким уровнем) → стоп в б/у
  TP2: X
  R:R ≈ N:1 к TP1

📣 Это сигнал: вход, стоп и цели — в сетапе выше.
```

### 6.2. Watch
```
👀 Maga AI watch — TICKER

Жду нормальную точку входа — пока без сделки

⏸ причина (из валидатора: что именно не прошло и какой порог)

  🎯 Зона идеи: X–Y
  🏁 Цели: X · Y
  ❌ Отмена идеи: X
  🔑 Жду: конкретное условие → дам активный сигнал
```

### 6.3. Обновление / отмена (реплай на исходный пост)
```
⚡ TICKER — обновление по нашему разбору
что изменилось (данные) → новое решение (TP1 взят / стоп в б/у / идею отменяем / разворот)
```

### 6.4. Ответ в чате
Короткая свежая картина → 1–2 варианта (агрессивный / консервативный) →
блок «про плечо» из Risk Calculator → упоминание активной идеи по монете,
если она есть.

### 6.5. Разбор в личке
Вывод в 2–3 строки → 🔍 Проверка → 💡 Идея → 🎯 Сетап (или «сетапа нет и почему»)
→ что должно случиться для входа → за чем следить.

### 6.6. Прогресс-статусы
Пока агент работает, одно сообщение редактируется после каждого вызова
инструмента: «📊 Сверяю цены на биржах», «⛓ Смотрю ончейн», «📈 Смотрю
DEX-пары», «🌐 Ищу в вебе», «🧮 Считаю уровни». По готовности заменяется
ответом.

## 7. Модели

| Задача | Модель | ID | Настройки |
|---|---|---|---|
| Фильтр алертов, тексты обновлений статуса | Claude Haiku 4.5 (или бесплатная модель) | `claude-haiku-4-5` | короткий ответ, структурированный вывод |
| Caller: новая идея и сценарий | Claude Sonnet 5 (Claude Opus 5 — если нужна глубина) | `claude-sonnet-5` / `claude-opus-5` | один запрос, данные уже собраны, JSON на выходе |
| Чат-бот в группах | Claude Sonnet 5 | `claude-sonnet-5` | агент, лимит шагов ~8 |
| Ресерчер в личке | Claude Opus 5 | `claude-opus-5` | агент, effort `high`, лимит шагов ~20, веб-поиск |

Цены за 1M токенов (вход / выход): Opus 5 — $5 / $25, Sonnet 5 — $2 / $10,
Haiku 4.5 — $1 / $5.

Практика:
- модель задаётся конфигом, чтобы можно было менять без правки кода;
- **кеширование промпта** для системного промпта и описаний инструментов;
- модель caller'а возвращает **структурированный JSON** (направление, вход,
  стоп, цели, тексты «Идея» и «Проверка»), текст поста собирает Renderer;
- дневной лимит шагов на пользователя (у оригинала — 50) для контроля расходов.

Оценка стоимости:
- кол (1–2 запроса по 10–20K токенов): ~$0.03–0.06 на Sonnet 5, ~$0.1 на Opus 5;
- фильтр алерта на Haiku: < $0.01;
- разбор в личке (15–20 шагов): ~$0.3–0.9 на Opus 5, ~$0.1–0.35 на Sonnet 5,
  с кешированием в 2–3 раза меньше.

## 8. Хранилище (минимальная схема)

- `alerts` — id, источник (Ultra), тикер, тип, метрики, время.
- `tokens` — резолв тикера: CoinGecko id, контракты по сетям, пары по биржам.
- `ideas` — id, тикер, направление, статус, зона входа, стоп, цели, уровень
  отмены, условие watch, параметры валидатора на момент выпуска, создана/обновлена.
- `idea_events` — переходы статусов, цены, id сообщений Telegram.
- `messages` — id сообщения, чат, ветка, связанная идея (для реплаев).
- `conversations` — память диалогов по пользователю/чату.
- `usage` — шаги и токены по пользователю за день.

## 9. План разработки

1. **Каркас данных.** Ticker Resolver, обёртки бирж (цены, OI, фандинг, L/S,
   свечи, стакан), Feature Calculator. Проверка на 20–30 монетах.
2. **Валидатор и Risk Calculator** с тестами на примерах из раздела 1
   (все пять опубликованных колов должны проходить, PENGU/RE — отклоняться).
3. **Ресерчер в личке**: агент с инструментами, прогресс-статусы, шаблон 6.5.
4. **Caller**: приём алертов Ultra → фильтр → анализ → валидатор → пост в ветку.
5. **Состояния идей и Price Monitor**: watch → active → обновления реплаями.
6. **Чат-бот в группах**: упоминания и реплаи, общая память идей.
7. **Ончейн и DEX**: EVM/Solana/TON/Tron, GoPlus, DexScreener.
8. **Индексатор Robinhood Chain.**
9. **Новости и соцсети**: RSS, Telegram-юзербот, X.
10. **Калибровка**: журнал результатов колов (TP/стоп), подбор порогов
    валидатора по статистике.
