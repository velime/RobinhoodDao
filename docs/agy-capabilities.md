# Возможности agy (Antigravity CLI) для Bottom

Источник: `agy changelog` и `agy --help`, версия agy 1.5.6 (12.11.2026). Номер в скобках — версия changelog, где это появилось или изменилось. То, чего в changelog нет, помечено «не проверено».

## Режимы запуска

- `agy -p "<промт>"`: один запрос без диалога. Bottom использует именно его (`bottom/llm/agy.py`) с `--output-format json --dangerously-skip-permissions`.
- Вывод JSON содержит `finished_reason`: `print_timeout`, если истёк `--print-timeout` и ответ неполный, `interrupted`, если запуск прервали (1.4.11). При истечении `--print-timeout` код выхода 3 (1.5.0).
- Без `--print-timeout` запуск ждёт фоновые задачи до конца, раньше был скрытый лимит 30 минут (1.5.0). Зависание из-за фоновой задачи теперь заканчивается за 30 секунд (1.5.5).
- В `-p` не строится заголовок беседы и индекс поиска, CPU заметно меньше (1.5.2, 1.4.7).
- `--agent <имя>` с несуществующим именем даёт код выхода 1 и список агентов (1.3.4).
- `--mode accept-edits|auto|plan`. Режим `auto` на Windows 11 24H2+ для личных аккаунтов (1.4.4): безопасные команды выполняются без вопросов, опасные подтверждаются.
- `--input-format stream-json` + `--output-format stream-json`: по одному сообщению на строку, один ход на каждое. `--json-schema` задаёт структуру итогового ответа.
- `agy acp` (сервер Agent Client Protocol), `--remote-agent`, `remote-control`, `--sandbox`, `--settings`: в Bottom не используются.

## Модели и effort

- Доступные модели (`agy models`, 12.11.2026): `gemini-3.8-flash-low|medium|high`, `claude-sonnet-4-6`, `claude-opus-4-6-thinking`, `gpt-oss-120b-medium`.
- У `gemini-3.8-flash` effort входит в имя модели. Флаг `--effort` для некоторых моделей отклоняется (`--effort is not supported for model ...`). Учтено в `bottom/llm/agy.py`.
- `--model` без суффикса effort берёт уровень по умолчанию (1.3.4).
- Gemini 4 Carbon (Low/Medium/High) доступен только при входе через Application Default Credentials (1.5.5).

## Субагенты, плагины, MCP

- Субагенты и их модель видны в `/agents` (1.5.3). Плагин объявляет субагентов в корневом `agents.json` (1.3.3).
- `agy plugin install|list|validate`, `agy mcp add|list|...`. На этой машине плагинов и MCP-серверов в agy нет.
- Субагенты и рабочие swarm получают копию репозитория вместе с неподтверждёнными изменениями (1.5.5).

## Swarm (preview, 1.5.5)

- Запуск: слеш-команда `/swarm <задача>`. Основной агент становится координатором и добавляет рабочих. Каждый рабочий ведёт отдельную беседу, работает параллельно и общается через общую доску сообщений.
- Рабочего можно ответвить от беседы существующего участника. Каждому рабочему можно выбрать любую модель из `/model` (то есть Gemini, Claude и GPT-OSS вперемешку).
- Рабочий при исчерпании квоты встаёт на паузу, а не повторяет запросы. Рабочий-монитор сообщает координатору, если весь swarm завис.
- `/swarm board` (или `alt+s`): полноэкранный просмотр с составом, лентой сообщений и панелью чтения. Строка `Swarm(...)` в списке активных задач.
- Помечен `(Preview & Quota Heavy)`: каждый рабочий отдельный агент и тратит квоту.
- Не проверено: работает ли `/swarm` в `agy -p` (headless). В changelog про это ничего нет. Есть только флаг `--disable-slash-commands` («отключить раскрытие слеш-команд и навыков в режиме print»), из чего следует, что в print-режиме они раскрываются по умолчанию. Это надо проверить маленькой задачей.

## Ограничения для автоматического использования

- Длинные запросы к серверу Google рвутся через туннель с `unexpected EOF` (наблюдалось 12.11.2026 при effort `high` и большом входе). Короткие запросы проходят. См. также `docs/idea-token-savings.md`.
- Пустой запрос в `-p` стоит около 6800 входных токенов: накладные расходы самого agy.
- `--dangerously-skip-permissions` в `-p` отклоняет без вопроса команды и доступ к файлам вне рабочей папки, которые администратор Gemini Enterprise требует проверять (1.5.2).
- agy делает снимок необработанных файлов репозитория, в котором лежит рабочая папка, и пишет ошибки для бинарников. Рабочую папку стоит держать вне больших репозиториев.

## Swarm и gemini-arena

Это разные инструменты, swarm arena не заменяет.

- Swarm делит одну задачу между рабочими, которые сотрудничают через доску. Цель: сделать задачу быстрее и шире.
- Arena (`gemini-arena`) запускает N конкурентов на одну и ту же задачу: они атакуют и защищают решения друг друга по сетке на выбывание, судьи оценивают вслепую по рубрике, а финал оценивает Claude. Цель: выбрать лучший из N решений под давлением критики. В swarm такого соревнования, слепой оценки и рубрики нет.
- Arena работает на обычных `agy -p` и управляется скриптом `drive.py`, это предсказуемо и возобновляется с диска. Для swarm headless-режим не подтверждён.
- Расход у обоих большой. Arena на 4 конкурентов: 19 запусков, около 5 млн токенов (по замеру в навыке).

Вывод: arena оставить. Когда понадобится параллельная работа над частями одной задачи, проверить `/swarm` на маленькой задаче.
